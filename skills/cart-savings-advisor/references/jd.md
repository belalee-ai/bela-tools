# 京东：录入与核对

会籍名称、年费、优惠门槛和权益以当前账户页面为准。不要将历史活动的价格、预售形式或福利当成本次规则。

## 报价与会籍

- price 是完整单件券前价，已包含的单品直降不重复计算；店铺券、平台券、国补分别登记。
- 同款普通价和会员价写为同一商品的多个 offers。会员价必须带 `requires_membership:true`；旧数据 tags 中的 plus 也会触发会籍限制。
- membership.fee 填本账户实际开通价。未知不能当免费；已持有填 owned:true，本次不重复计入已付年费。
- 缺普通报价时，可以列出会员方案，但不能证明开会员比不开省了多少。不同人的券包不能拼成同一账户的可执行方案。

## 券和其他支出

- 店铺券放 shops，平台/品类券放平台 coupons，会员专属商品款券放 membership.coupons。
- 每张有门槛的券明确 threshold_on；同层多组叠加券明确 stack_group 与 order。京东不共享任何未经核实的淘宝默认规则。
- 运费写店铺 shipping；有包邮门槛时明确 threshold_on。运费券写该店 shipping_coupons，只抵实际运费；会员限定运费券标记 requires_membership:true。
- 一张跨店通用运费券不能复制为每店一张。目前模型只支持指定店铺的运费券库存；范围不确定时按无运费券金额并标明待核实。
- 包装与服务费写 packaging_fee / service_fee，每店每次结算计收。已付定金写在报价 deposit_paid，不能当作优惠。
- 国补必须有 confirmed、group、limit，可加 cap 与 total_cap；资格共享，不因换平台而恢复。
- 模型允许放弃可选优惠；优惠被强制使用、顺序不同或存在未建模的预售规则时，须核对结算预览后再给可执行建议。

## 数据与交付

读用户录屏/截图，或用已连接且验证可用的浏览器只读购物车。遇到登录或验证码由用户处理。逐单核对商品规格、优惠库存、运费、定金和本次待付，不替用户提交订单或付款。
